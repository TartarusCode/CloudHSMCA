# roles-anywhere

The first consumer of [`../hsm-ca`](../hsm-ca): an **IAM Roles Anywhere** trust
anchor, the workload profiles that decide which certificate gets which role, and a
Lambda that activates the anchor and keeps its CRL current.

```hcl
module "roles_anywhere" {
  source = "git::https://github.com/TartarusCode/CloudHSMCA.git//modules/roles-anywhere?ref=main"

  ca_contract = module.hsm_ca.ca_contract

  workload_profiles = {
    ci-runners = {
      session_duration_seconds = 3600
      managed_policy_arns      = ["arn:aws:iam::aws:policy/ReadOnlyAccess"]
      allowed_subject_ou       = "CI"
    }
  }
}
```

## One apply, no circular dependency

`CreateTrustAnchor` needs a certificate bundle, but the real chain only exists after
a ceremony. So the module creates a **throwaway self-signed certificate** (CA:TRUE,
one year) and a trust anchor around it with `enabled = false` and
`ignore_changes = [source, enabled]`, so a later plan never overwrites the live chain
or re-disables the anchor.

## What activation does

The module's Lambda has two triggers and is the only thing that changes the anchor:

| trigger | behaviour |
|---|---|
| `cloudhsmca.pki` / `CAChainPublished` | `UpdateTrustAnchor` with the published chain, `EnableTrustAnchor`, sign a DER CRL with the KMS Intermediate key, `ImportCrl`, `EnableCrl` |
| `rate(24 hours)` | re-sign and re-import the CRL; while the chain still reads `PENDING-CEREMONY`, return `{"skipped": "chain-not-published"}` without touching anything |

The role is named `<ca_name>-crl-issuer`, which is what the engine's key policy
matches on for `kms:Sign` — the two modules share a naming convention, not a
resource reference.

Revoked serials are read from `s3://<artifacts>/<revocations_s3_key>` (default
`revocations/revoked.json`) as JSON:

```json
{"revoked": [{"serial": "0x5f89eca173f0e5", "reason": "key_compromise"}]}
```

Invoke the function with any payload to import immediately instead of waiting for
the next tick:

```bash
aws lambda invoke --function-name <crl-issuer-function-name> \
  --payload '{"reason":"manual"}' --cli-binary-format raw-in-base64-out /dev/stdout
```

## Profiles

Each `workload_profiles` entry becomes an IAM role and a Roles Anywhere profile.
`allowed_subject_ou` / `allowed_subject_cn` are written as conditions on the
certificate subject (operator configurable via `subject_condition_operator`),
`managed_policy_arns` and `session_policy_json` bound what the issued credentials can
do, and `session_duration_seconds` is validated against the STS range (900–43200).
`accept_role_session_name` defaults to `true`.

`rolesanywhere_update_env` in the root module prints the signing-helper exports for
the whole stack.

## Testing

```bash
make test    # tests/lambda: activation, scheduled refresh, the no-chain skip, the
             # no-chain activation failure, plus the CRL verified with openssl
```

The handler is extracted from `crl_issuer_lambda.tf`'s heredoc — the bytes that get
zipped, not a copy — and run against stubs, so the harness fails if the shipped
script and the tested script ever diverge.
